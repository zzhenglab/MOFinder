## What the classification means

**These topic classifications are not generated by an LLM.** They are rough,
deterministic classifications based on article titles, abstracts, and document
types, intended for a broad descriptive analysis. They have not been validated
against expert topic labels and should not be treated as ground truth.

Each DOI has one of four topics based on the reported primary contribution:

- Chemical synthesis: synthetic-route development, molecular/ligand synthesis,
  or post-synthetic chemistry; routine framework preparation is weak evidence.
- Theory & modeling: primarily computation/theory, plus identified review
  articles under this analysis's review policy.
- Crystal engineering: constructing or understanding coordination structures,
  networks, and topology, including new frameworks with substantial structural analysis.
- Functional materials: application/property performance, including derived
  materials and catalysts used to make molecular products.

The [public classifier source](../../../tools/literature_triage/topic_classifier.py)
defines the exact precedence and evidence patterns.

All papers receive a topic, but assigning a topic does not resolve every
uncertainty. `Review needed`, `Review reason`, `Low confidence`, `Fallback used`,
`Fallback basis`, and `Classification method` retain weak evidence, ambiguous
assignments, and fallback provenance. Overall, 8,925 assignments retain a review
flag. The compact DOI table omits these details for convenience; use the audit
for interpretation.

`Triage decision` is a **separate, previously saved model Y/N decision** about
inclusion for synthesis-information extraction. It is not the source of the
topic label and was not changed to obtain a desired category balance. The
retrieval inventories contain the Y set; the full DOI and audit tables include
both Y and N. Every paper is counted once in corpus-level topic summaries.

| Category | Before triage | After triage (Y) | After triage (N) |
| --- | ---: | ---: | ---: |
| Chemical synthesis | 2,017 | 879 | 1,138 |
| Theory & modeling | 500 | 85 | 415 |
| Crystal engineering | 4,862 | 2,968 | 1,894 |
| Functional materials | 6,391 | 3,503 | 2,888 |
| Unclassified | 0 | 0 | 0 |
| **TOTAL** | **13,770** | **7,435** | **6,335** |

All 124 previously unclassified papers now have provisional topic assignments.
Of these, 77 use broad lexical fallback and remain explicitly flagged as low
confidence; none uses the unsupported corpus-domain default. The remaining 47
are assigned by expanded topic rules. Chemical synthesis still has more N than
Y under the primary-topic definition above; the recorded triage decisions and
category rules were not adjusted to force a preferred ratio.

Duplicate bibliography rows use a single canonical representative selected by
title/abstract text length. `Bibliography row` records that representative's
original workbook row (the header is row 1), which also identifies the record
position in [`literature_metadata.csv`](../literature_metadata.csv). `Document
Type` is retained in the audit because it is not part of that six-field export.
This representative choice does not resolve the separate duplicate-conflict
check used by whole-corpus LLM screening.

## Reproducing the publication

The complete upstream notebook analysis reads the original local workbooks.
The public classifier source, bibliography metadata, and audit document types
make the topic rules and canonical inputs inspectable. Source hashes, classifier
version, label counts, uncertainty counts, and output hashes are recorded in
[`manifest.json`](manifest.json).

After regenerating the upstream analysis, publish its completed audit from the
repository root:

```bash
python tools/publish_literature_classification.py ../literature_triage/outputs/full_decision_audit.csv --analysis-manifest ../literature_triage/outputs/run_manifest.json --classifier tools/literature_triage/topic_classifier.py
```

The publisher validates exact DOI coverage, unique audit identities, canonical
bibliography rows, resolved Y/N decisions, and agreement between the retrieval
inventories and the Y set before writing. It preserves retrieval row order and
duplicates and refreshes both metadata manifests. It does not run an LLM or
generate new topic labels.

## Local download progress and documents

Published CSVs omit `Downloaded` and `SI Downloaded`. The desktop applications
initialize blank status columns in local working inventories and preserve topic
classifications when saving progress. Existing working inventories can still
be selected to resume a download run. The source file hash identifies a working
copy, so updating a published input starts a new copy unless the previous working
file is explicitly selected. See the [retrieval guide](../../../docs/literature_retrieval.md).

Article PDFs and supporting-information documents are not included. Store
downloaded copies in the configured local directories. A small DOI table and
replaceable article/SI templates are available in the API demo's
[literature input folder](../../../Demo/03_api_demo/literature_input/README.md).
